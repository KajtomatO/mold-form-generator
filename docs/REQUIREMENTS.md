# Casting Form Generator: requirements

This file records every original requirement, every decision made since, and where a decision changed the original text. `docs/PLAN.md` describes how it gets built.

## 1. Purpose and glossary

The app takes a user's STL and generates a printable two-part plastic container. Silicone poured into the container becomes a casting mold, using far less silicone than a plain mold box.

| Term | Meaning |
|---|---|
| Model | The user's STL, the object the finished mold duplicates. |
| Model-base | All model faces on the flat plane that stands on the base, even when disconnected, such as two legs. |
| Base | Flat rectangular plate carrying the model. |
| Cover | Box whose inside follows the model, with pour openings in its flat top. |
| t | Silicone thickness, the minimum free space between model and cover. |
| Top envelope h(x,y) | Highest model surface in each XY column. |
| H(x,y) | Cavity ceiling height over each XY point. |
| r_eff | Dilation radius: t plus a safety margin. |
| Tool | The closed solid {0 <= z <= H} subtracted from the cover. |
| Jacket | The cured silicone. |
| Mode A | Model printed separately and glued into a pocket in the base. |
| Mode B | Model merged into the base STL. |

Coordinates: base plane z=0, cavity above it, base from z=-Tb to 0.

## 2. Original requirements, verbatim

> Create a step-by-step implementation plan of an web apllication:
> This application will take an user stl model and will allow to generate a "container" to be filled by silicon to create a casting mold. The role of the container is to reduce usage of silicon in form creation.
> The user provided stl is a model to be duplicated by the final silicon mold. This silicon mold will be crated by using models created by this tools.
> The "container" generated by this tool, will be composet by two parts, a "base" and the "cover".
> The base and the cover fit toghether to create a plastic mold to create the final silicon mold.
>
> It is assumed, that user provided model have at least one flat face, that can be directly attached to the base. Lets call this face: "model-base"
> The base will be a mostly flat rectangle With enought depth to not woble [3mm min]. The user's stl (or a physical model) will be:
> a.) Glued by user to the base. User then can use resin printer to print higly detailed model, and FDM printer for the rest. In this case, the base should have shallow [configurable 0.1mm default] cut-out of the "base", it should be bigger by 0.2mm [again, configurable] to allow for a tollerance.
> b.) Be part of the base stl model.
> User chan chose between mode's a and b.
>
> The cover, will be a shape that encloses the user model. Externaly - it will be a box. Internally it will be a shape that mimics the shape of the user model + 3mm [configurable, lets call this parameter - silicon thickness]
> Important: This does not mean, that the user model should be scalled by "silicon thicknes", this will not work. There have to be added a layer of "silicon thiknes" to almoust every face of the user's model, to make it "fatter" and then there should be a boolean operation to extract this shape from the cover. This will create a constant free space between [base with user model] and the [cover].
>
> Note: Depending of user model shape, when making it bigger you should not move the face of "model-base". Some other faces could expand to cross behind the plane of "model-base", they shoudl be trimm to the plane of model base [in practice - they will 'touch' base]
> If all faces on "model-base plane" are considered a "model-base" - even if not attached to themself [example legs].
>
> The base and the cover, when put together will make a closed volume - with exceptions of pouring openings in cover.
> The cover should have an cut out with a matching chamfer for the base - so they can be easly put together.
>
> User can chose to create a grid of identical models in a mold. Size [x,y], spacing between models, and distance from the edge should be configurable.
>
> The pouring openings - the number can be configurable, but minimum of 1 per model. If more than 1 per model, it should be spread around the center of the model. Position should be cofigurable in gui - drag and drop.
>
> The pouring openings - default diameter [10mm], on the external part of the cover, there should be a configurable cut-out for a funnel. Funnel's model can also be generated.
> Note: The cover, have to be box-shaped. On one side - the opening for the base, on the oposite side - the pouring openings. With the exception of the pouring openings, this side should be flat.
>
> Example of usage of finished product by the user:
> 1.) User prints his model, base and the cover.
> 2.) He glues his model to base.
> 3.) He connects base to cover, creating an enclosed space of depth of 3mm around his model with a pouring opening on the other side.
> NOTE: To minimalise leckage of silikon, and work needed to seal both of them, the connetion between base and cover is importnat.
> 4.) He inserts the funnel into pouring openning, and pours the silikon.
> NOTE: The pouring oppening should be on the "highest" point of the open space inside, otherwise the silicon will not reach all spaces.
> 5.) After silikon hardens, user removes base with his model and detaches the funnels. The remaning silikon - with the cover - becomes a final mold.
> NOTE: This is why the "box shape" of the cover, and flat "top" is important, it becomes the bottop of final form.
>
> The apllication should fully run in user browser - no back end.
> The gui should give -if possible- a realtime prieview of the shape of the base and the cover.
>
> There should be an option to add scalable geometry primitves [box, cone, cilinder] to the user model. Those shapes will be used ONLY for creation of cutout in the cover.
> This will be useful, when model have some shapes, that would make de-molding impossible - silicon is flexible, the cover is not.
> Example: a person standing on two legs. If the space between legs will be filled by the cover, then removing final model will not be possible -> silicon is flexible, and can be cut for de-molding [this does not imapct reusing it] - plastic of cover will make it impossible.
> Question: Perhaps it is posible to simulate this, and modify shape of cover to allow pulling out model? It would reqire cutting out more of the cover in certain places. Perhaps the model that is used for the boolean operation, never should narrow when aproching the model-base. If this is possible, skip the geometry primitives.
>
> Note: To create the cover, If user have a very detailed model, try to simplify it first and then "add layers"
>
> There should be a file detailing all of those requrements.
> Note: You are on headles server. If you need additional software, create me a script that will install it.
> Use https://bumpmesh.com/ as reference of gui design.
> For now this will be only local deployment.
> Init git now, and then commit by yourself, but do not add yourself in commit description.
> Ask questions.

Follow-up from the user: "I assumed first version will use adhesive tape, but you can add some connection system with nuts and bolts - just remember to make it FDM-priner friendly".

## 4. Decisions

Agreed with the user on 2026-11-07.

| ID | Decision | Changes |
|---|---|---|
| D1 | The cavity never narrows towards the base (a height field over the base plane). No geometry primitives and no uniform-shell mode. | R08, R09, R22, R23 |
| D2 | The cured silicone can slide out of the cover. Workflow: cut sprues, remove silicone with the model inside, cut or flex, take out the model, re-seat. The app reports for each model whether pulling inside the cover is plausible and where cuts are likely. | R17 step 5 said the base and model are simply pulled out. Research shows this often fails with overhangs, since rigid walls stop the silicone flexing. |
| D3 | First pour at the highest point, a 2 to 3 mm vent beside it and at each other significant peak. Extra pours take next-highest peaks, then spread around the centre. All are draggable. | R14 said spread around the centre. R16 gains vents in the flat top. |
| D4 | Joint is a taper plus tongue and groove: a ridge on the base fits a groove in the cover's shelf. A printable fit-test piece is generated. | R12 said a matching chamfer. |
| D5 | Adhesive tape in version 1. Optional nuts and bolts later: countersunk bolts up through the base into hex nuts slid into side slots in the cover's corners, with nothing through the flat top and no supports needed. | R18, R31 |
| D6 | Layer height setting, default 0.2 mm. Pocket depth defaults to one layer, any depth can be set, and the app warns if it is not whole layers. Enlargement stays 0.2 mm. | R05 said 0.1 mm, which is likely to print as 0 or 0.2 mm at 0.2 mm layers. |
| D7 | Served on plain `http://192.168.0.153:5173`, which is not a secure context. | Adds the constraints in section 6. |
| D8 | Build all milestones in order, committing each once its tests pass. No Claude attribution. Physical print checks are left to the user. | R29 |
| D9 | Silicone thickness default stays 3 mm, configurable. | none |

### Additions accepted with the plan

The user approved these on 2026-11-07 as part of the plan.

| ID | Addition | Reason |
|---|---|---|
| A1 | The cover is never simplified before offsetting. `model_oriented.stl` always comes from the original mesh. | Rasterising at 0.125 mm already removes finer detail and tolerates non-watertight input. |
| A2 | Base stands 0.2 mm proud of the cover's bottom edge, not exactly flush. | First-layer squish could otherwise recess the base, so tape would stop loading the seal. |
| A3 | One pour per body, not per connected cavity. | `jersey-barriers-x8.stl` forms 2 cavities at defaults, but each of its 8 bodies needs a pour. |
| A4 | 1 degree wall draft, closing of plastic fins under 1.2 mm, pry notches, 3 mm plate corners, base default 4 mm, Mode A default. | Removal, printability, and stability. |
| A5 | Grid spacing defaults to auto, keeping a printable wall, until the user types a value. | A fixed 10 mm leaves thin dividers on tall models. |
| A6 | `edge` is a minimum, and the app says when it raised the value. | The seal must fit between cavity and box wall. |
| A7 | Islands smaller than `minIsland` (default 5 mm2) are dropped from the footprint and listed in Diagnostics. | Wolf has 9 footprint components, of which 6 are tiny. |

Default silicone is higher than the earlier estimate shown to the user, because of the safety margin and draft. Estimated ml at defaults: Benchy 43, Goddess 118, VIS-35 544, jersey 11.8, x8 92, barrel 10.2, wolf 208.

Accepted by the user with the plan. None was an original requirement: mesh remesh repair, tunnel counting, dead-end well analysis, casting-phase air analysis, fill-time estimate and silicone presets, strain estimate, autosave, sloped roofs over flat ceilings, top-down inset view.

## 5. Derived engineering rules

These follow from research and design review. `docs/PLAN.md` has the full construction.

| Rule | Statement |
|---|---|
| Margin | `r_eff = t + 2.13*cellFinal + printMargin`, plus a vertical raise of the TIN tolerance. Measured by `minGap`; export raises it automatically if needed. |
| Print pose | The cover rotates, `(x, -y, Zt - z)`. A plain z flip mirrors the cavity. |
| Conditioning order | Draft first, then closing. The other order leaves tall thin plastic blades. |
| Rim | Rim dimensions are derived from analytic cavity bounds and never entered directly. |
| Joint clearance | `cG` is larger than `cT`, so the ridge is never first contact. |
| Funnel seat | Always a cone, never a counterbore, which would need supports and form a locking head. |
| Sprue | Without a funnel, the sprue is cut at the seat floor, not flush with the top. |
| Interval overlap | Neighbouring silicone intervals connect only if they overlap by at least one cell. |
| Silicone volume | Sealed air and internal voids are excluded. |
| Vents | Every significant peak gets a vent, even a long one, with a warning. Auto vents can be deleted. |

## 6. Constraints

- All geometry runs in the client browser. The server only serves files.
- Over plain http on a LAN address these are unavailable and must not be used: SharedArrayBuffer, WASM threads, WebGPU, OPFS, service workers, Web Crypto, `showSaveFilePicker`, async clipboard.
- Downloads use a Blob and an anchor. Chrome may ask to keep or discard them.
- BumpMesh is AGPL, so no code, markup, styles, icons or assets are copied. Layout conventions only.
- Libraries are self-hosted through the bundle, with no CDN at runtime.

## 7. User workflow as implemented

1. Print model, base and cover.
2. Glue the model into the pocket (Mode A). Test the adhesive for cure inhibition first.
3. Join base and cover. Seal with tape, optionally Vaseline in the groove, or with the bolts turned on: fit the nuts into the cover's side slots, then turn the 4 countersunk screws up through the base's corners until snug, with tape across the middle of a side longer than about 100 mm between bolts.
4. Insert the funnel and pour through the pour opening, watching silicone reach the vents.
5. After curing, cut the sprues.
6. Remove the silicone with the model inside it from the cover, cut or flex it, take out the model, and re-seat the silicone in the cover. Mild shapes may release while still in the cover, and the app says which.
7. The silicone in the cover is the finished mold, with the cover's flat top as its bottom.

`docs/WORKFLOW.md` will hold the full version.
